# Kompass API Contracts

> Full detail lives in the team's Kompass API Contracts doc; this file is the in-repo summary.

Changes to this file, `api/app/schemas/shared.py` or `app/src/types/api.ts` need approval from both @faraz999shah and @willapat. Change all three together.

## Conventions

- Base path `/v1`, JSON bodies, `snake_case` keys
- Scores and confidences are decimals from 0 to 1
- Money is an integer plus an ISO 4217 currency code (`USD`, `MXN`, `KES`)
- Error shape on every endpoint:

```json
{"error": {"code": "string", "message": "string", "details": {}}}
```

## LearnerProfile

Will's API writes it; Faraz's API reads it. It is the only handoff between the two APIs.

```json
{
  "user_id": "u_8f3c2a91",
  "country": "KE",
  "language": "sw",
  "accessibility": {
    "voice_mode": true,
    "read_aloud": true,
    "simple_mode": true,
    "large_text": false,
    "speech_rate": 1.0
  },
  "life_stage": "student",
  "goal": "save_more",
  "comfort": 1,
  "savings_habit": "cash_at_home",
  "topic_scores": {
    "accounts": {"confidence": 0.6, "quiz_score": 0.5, "proficiency": 0.54, "completed": false}
  },
  "bonus_lesson_ids": [],
  "updated_at": "2026-10-15T15:30:00Z"
}
```

`topic_scores` has one entry per topic.

**proficiency = 0.4 × confidence + 0.6 × quiz_score**, rounded half up to 2 decimals. If the quiz is skipped, `quiz_score` is `null` and proficiency equals confidence.

## LearnerNeeds

Built by Faraz's API from the World Bank Global Findex Database 2025 (`data/findex/`, generated by `data/scripts/process_findex.py`). It says what people like the learner (same country and age group) need. The Lessons API reads it together with `LearnerProfile` to customize lessons and order the path. Rates and gaps are decimals from 0 to 1.

- `age_group` comes from `life_stage`: `student` and `first_job` → `ages_15_24`; `parent` and `retired` → `age_25_plus`. When Findex publishes no age split for an indicator, that signal uses `all` adults.
- Each indicator becomes a signal of one `kind`: `struggle` (e.g. would find emergency money very hard), `lacking` (e.g. no bank savings), `could_use` (e.g. interest on savings) or `exposure` (scams: Findex has no fraud question, so digital payment use stands in for exposure).
- `gap` compares the group to the benchmark (upper-middle-income average): for higher-is-better rates `(benchmark − rate) / benchmark`, for lower-is-better `(rate − benchmark) / (1 − benchmark)`, clipped to 0–1. For `exposure`, `gap` is the share exposed.
- `findex_gap` is the mean gap of a topic's signals and feeds the path priority formula. `priorities` lists topics by `findex_gap`, biggest first.
- `struggles`, `lacking` and `could_use` list every signal of that kind with a gap above 0, biggest first.

```json
{
  "user_id": "u_8f3c2a91",
  "country": "KE",
  "age_group": "ages_15_24",
  "benchmark_name": "upper-middle-income countries",
  "source": "World Bank, The Global Findex Database 2025",
  "topic_needs": {
    "saving": {
      "topic": "saving",
      "findex_gap": 0.3967,
      "signals": [
        {"indicator_id": "fin17a", "label": "saved at a bank in the past year", "kind": "lacking",
         "group_rate": 0.2031, "age_group": "ages_15_24", "benchmark_rate": 0.5408, "gap": 0.6244, "survey_year": 2024}
      ]
    }
  },
  "priorities": ["scams", "accounts", "borrowing", "saving", "budget"],
  "struggles": [],
  "lacking": [],
  "could_use": []
}
```

## Endpoints

### LearnerProfile API (Will)

| Method | Path |
|---|---|
| POST | `/v1/onboarding` |
| POST | `/v1/quiz/{quiz_id}/submit` |
| POST | `/v1/quiz/{quiz_id}/skip` |
| GET | `/v1/profile/{user_id}` |
| PATCH | `/v1/profile/{user_id}/accessibility` |
| POST | `/v1/profile/{user_id}/lesson-results` |

#### Onboarding and baseline quiz

`POST /v1/onboarding` request (`accessibility` is optional; every topic needs a confidence from 0 to 1):

```json
{
  "language": "sw",
  "country": "KE",
  "accessibility": {"read_aloud": true, "simple_mode": true},
  "life_stage": "student",
  "goal": "save_more",
  "comfort": 1,
  "savings_habit": "cash_at_home",
  "confidence": {"accounts": 0.6, "saving": 0.3, "borrowing": 0.2, "scams": 0.5, "budget": 0.4}
}
```

Response `201`: `user_id` plus the quiz, written entirely in the learner's language with country details (currency, ID, mobile money, deposit insurer) filled in:

```json
{
  "user_id": "u_8f3c2a91",
  "quiz": {
    "quiz_id": "qz_41d0a2b7",
    "language": "sw",
    "questions": [
      {
        "question_id": "qz_41d0a2b7_1",
        "topic": "accounts",
        "difficulty": 2,
        "prompt": "Ni njia gani salama ya kutuma pesa kwa familia haraka?",
        "options": [{"option_id": "a", "text": "M-Pesa"}, {"option_id": "b", "text": "..."}, {"option_id": "c", "text": "..."}],
        "voice": {"speak_text": "Swali la 1 kati ya 10. ... Chaguo A: M-Pesa. ... Sema A, B au C kujibu. Sema rudia kusikia tena."}
      }
    ]
  }
}
```

- 10 questions, 2 per topic in topic order, from the pre-written bank in `data/question_bank/`.
- Every learner gets one easy (difficulty 1) and one hard (difficulty 3) question per topic, easy first, regardless of their sliders. Everyone is measured on the same scale, so `quiz_score` 0 means missing the basics, 0.5 means basics only, and 1 means basics plus harder material. Confidence still counts through the proficiency formula.
- The answer key never leaves the server; it is stored with `quiz_id`.

`POST /v1/quiz/{quiz_id}/submit` request `{"user_id": "...", "answers": [{"question_id": "...", "option_id": "b"}]}`. Response `200` is `{"profile": LearnerProfile, "results": [{"question_id", "correct", "correct_option_id"}]}`. Unanswered questions count as wrong; an unknown question or option, or the same question twice, is `400 validation_error`.

`POST /v1/quiz/{quiz_id}/skip` request `{"user_id": "..."}`. Response `200` is `{"profile": LearnerProfile}`.

Submitting or skipping a finished quiz returns `409 quiz_already_submitted`; a quiz that does not exist or belongs to another user returns `404 quiz_not_found`. `GET /v1/profile/{user_id}` returns `404 profile_not_found` until the quiz is submitted or skipped.

#### Profile updates

`PATCH /v1/profile/{user_id}/accessibility` takes any subset of the accessibility fields, for example `{"voice_mode": true, "speech_rate": 0.8}`. Fields left out keep their value. Response `200` is the full `LearnerProfile`.

`POST /v1/profile/{user_id}/lesson-results` request `{"lesson_id": "saving", "correct": 4, "total": 5, "completed": true}`. Response `200`:

```json
{"topic": "saving", "proficiency": 0.55, "completed": true, "path_refresh_needed": true}
```

- New proficiency = 0.5 × old proficiency + 0.5 × (correct / total), rounded half up to 2 decimals.
- `completed` never goes back to `false` once a topic is finished.
- `path_refresh_needed` is `true` when the topic's difficulty band changed (below 0.4 → 1, below 0.7 → 2, otherwise 3), so the app calls `POST /v1/path` again.
- A bonus `lesson_id` from the profile's `bonus_lesson_ids` changes nothing in `topic_scores`; `topic` and `proficiency` are `null`. Any other unknown `lesson_id` returns `404 lesson_not_found`. `correct > total` or `total < 1` returns `400 validation_error`.

### Voice API (voice teammate)

| Method | Path |
|---|---|
| POST | `/v1/voice/transcribe` |
| POST | `/v1/voice/intent` |
| GET | `/v1/voice/speak` |

Speech runs on Gemini, server-side only (see `docs/adr/0007-gemini-for-speech.md`). Both endpoints are rate-limited per client (`429 rate_limited`) and return `503 speech_unavailable` if `GEMINI_API_KEY` is missing or Gemini fails twice in a row.

`POST /v1/voice/transcribe` takes `multipart/form-data` with `audio` (m4a, wav, webm, ogg, mp3 or aac, up to 5 MB) and `language` (`en`, `es` or `sw`, used as a hint). Response `200`:

```json
{"text": "How do I send money to my mom in another country?", "language": "en"}
```

Errors: `400 validation_error` (missing field, unknown language, empty recording), `413 audio_too_large`, `415 unsupported_audio_type`. Recordings stay in memory and are never stored.

`GET /v1/voice/speak?text=...&language=sw` returns `audio/wav` of the text read aloud (1–1000 characters). The app uses it only when the phone has no built-in voice for the language, usually Swahili. It is a `GET`, so an audio player can stream it straight from the URL; responses may be cached for a day.

## Lesson

`GET /v1/lessons/{lesson_id}` returns a lesson already customized for the learner. A core lesson's `lesson_id` is its topic (`saving`); bonus lessons have their own ids. It contains only the cards that fit their difficulty, life stage and goal, with Findex numbers for people like the learner and local country facts (currency, mobile money, deposit insurer...) from `data/question_bank/countries.json` filled in.

```json
{
  "lesson_id": "saving",
  "topic": "saving",
  "title": "Safe Saving",
  "goal": "Compare where money can be kept and understand protection and growth.",
  "difficulty": 2,
  "cards": [
    {
      "card_id": "protected-quiz",
      "type": "mc_quiz",
      "text": "Where is your money protected if something goes wrong?",
      "options": {"a": "In a licensed bank with deposit insurance", "b": "Under the mattress"},
      "correct_option": "a",
      "voice": {"speak_text": "...", "answer_mode": "say_option", "spoken_options": {"a": "...", "b": "..."}}
    }
  ]
}
```

Errors (contract error shape): unknown `user_id` → `404 profile_not_found`; unknown `lesson_id` → `404 lesson_not_found`; missing `user_id` → `400 validation_error`; a stored lesson or data file that cannot be customized → `500 lesson_build_failed`. If English simplification fails twice, the original English template is served. For Spanish or Swahili, failed or partial translations return `503 lesson_translation_failed`; English teaching is never silently substituted.

## Bonus lessons

`POST /v1/bonus-lessons` answers "teach me about X". The app sends the learner's question as text (typed, or transcribed by `/v1/voice/transcribe`), in any supported language:

```json
{"user_id": "u_8f3c2a91", "request": "Nifundishe kuhusu bima"}
```

One LLM call (prompt `lesson_generation_v1`) decides between:

- **A core lesson covers it** → that lesson, customized: `{"lesson": Lesson, "generated": false, "matched_topic": "saving"}`
- **A new money topic** → a new English base lesson (3–6 cards, `concept` / `bridge` / `mc_quiz` / `takeaway`, ending with a takeaway, at least one quiz, a `voice` block on every card). It is validated, stored, added to the learner's `bonus_lesson_ids`, customized with both models like a core lesson, and reworded into their language: `{"lesson": Lesson, "generated": true, "matched_topic": null}`. Its id starts with `bonus_`; `GET /v1/lessons/{lesson_id}` serves it again to the same learner only.
- **Not about personal money** → `422 off_topic_request`.

Generated lessons may not contain digits: every number or local fact must be a placeholder code fills (country facts such as `{cur}` and `{mobile_money}`, and the `LearnerNeeds` facts). Invalid replies are retried once, then `503 lesson_generation_failed`. Status `201` on success; unknown learner `404 profile_not_found`; empty or over-300-character request `400 validation_error`.

## Lesson cards

Card types: `concept`, `bridge`, `mc_quiz`, `drag_match`, `compare_chart`, `clause_tap`, `scam_swipe`, `budget_sim`, `takeaway`.

Every card has a **required** `voice` block, so every lesson, including AI-generated bonus lessons, can be played entirely by voice:

```json
"voice": {
  "speak_text": "Full spoken version of the card, including every option with its letter.",
  "answer_mode": "say_option | say_next",
  "spoken_options": {"a": "option text", "b": "option text"},
  "correct_feedback": "Spoken feedback when right (quiz cards only).",
  "incorrect_feedback": "Spoken feedback when wrong, including the explanation (quiz cards only)."
}
```

## Scoring

**priority = 0.4 × findex_gap + 0.4 × (1 − proficiency) + 0.2 × goal_match**

### Change lesson language without resetting progress

`PATCH /v1/profile/{user_id}/language` accepts `{"language": "en"}` and returns
`LearnerProfile`. The learner id, scores, completions and bonus lesson ids are
preserved. US/MX offer `en` and `es`; KE offers `en` and `sw`.
Unknown learner: `404 profile_not_found`; unsupported country/language pair:
`422 unsupported_language`; invalid or extra fields: `400 validation_error`.
Subsequent GET lesson and POST bonus-lesson requests use the saved language,
including question text, options and voice text, through `reword_lesson`.
Translation failures return `503 lesson_translation_failed` for non-English learners. The app displays a translated retry message.

## Server-personalized learning path

`GET /v1/path/{user_id}` returns `LearningPath`:

```json
{"user_id":"u_example","lessons":[{"lesson_id":"saving","topic":"saving","priority":0.7,"difficulty":1,"completed":false}]}
```

The response includes all five core lessons, scored from Findex gaps, saved
confidence/quiz proficiency, and the learner's goal. Completed topics appear
after unfinished topics. `404 profile_not_found` means onboarding has not
finished for this id. New profiles have no completed topics. The frontend
preview and roadmap fetch this response; completing a lesson invalidates it.
Bonus lessons retain their existing ids and stay linked to the same profile.
